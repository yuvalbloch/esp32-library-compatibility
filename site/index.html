How we test

For each library we take the newest release and up to three previous releases, pick one or two of the library's own example sketches, and compile them with arduino-cli against Arduino-ESP32 cores for the ESP32, ESP32-S3 and ESP32-C3 chips. Each core version is installed in its own sealed environment, and each compile is given exactly the library versions listed in its log.

This is a build test, not a hardware test. ✅ means the example compiled and linked. It does not prove the library behaves correctly at runtime. ❌ is a strong signal: the code cannot be built with that setup.

What the symbols mean

Rules we follow

  • Every status comes from a real compile log. Nobody (human or AI) sets a ✅ or ❌ by hand.
  • Results never change. A library fix shows up as a new library version with its own row.
  • If an example needs a library its own library does not declare (for example a display driver needing a graphics library), we add the library that provides the missing header and record it in the log.
  • If a sketch is too big for the default flash layout, we also try the huge_app partition scheme and show the result with ⚙.
  • Compiler warnings use the Arduino IDE default (warnings off).

Which libraries

The most popular ESP32-compatible libraries from the Arduino Library Manager, ranked by popularity and by how likely the new core was to break them. Libraries marked Espressif CI are also checked by Espressif's own test, which compiles about ten external libraries; we include them so you can compare.
